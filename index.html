A Hybrid Home SOC Lab

A hands-on cybersecurity laboratory built from the ground up to simulate an attacker, a defender, network security controls, centralized logging, detection engineering and SOC investigation — entirely on local infrastructure.

View GitHub Repository Explore Architecture

Why This Lab Exists

Instead of learning cybersecurity tools in isolation, this lab connects the entire attack-to-detection lifecycle.

⚔

Attack Simulation

Kali Linux is used to generate realistic security activity against vulnerable applications such as DVWA and OWASP Juice Shop.

🛡

Network Defense

pfSense provides the perimeter firewall, routing, segmentation, VLAN isolation and network-level visibility.

🔎

SOC Investigation

Logs are centralized into ELK so attacks can be searched, correlated, investigated and converted into detections.

SOC Analyst Workflow

The objective is not simply to generate attacks, but to understand what happens after the attack.

1

Generate

Perform reconnaissance, authentication attacks or web exploitation from Kali.

2

Collect

Capture firewall, host and application telemetry generated during the attack.

3

Detect

Create rules and identify suspicious patterns inside centralized logs.

4

Investigate

Pivot through timestamps, source IPs, users, requests and related events.

Detection Engineering

Custom detections are being developed around common attack techniques reproduced inside the lab.

Rule 100010

SQL Injection activity detected in web application logs.

Rule 100011

Path traversal patterns detected in HTTP requests.

Rule 100012

Command injection indicators detected in application traffic.

Rule 100013

Suspicious web attack patterns identified from request data.

Rule 100014

SSH brute-force authentication activity.

Rule 100015

Repeated authentication failures from a single source.

Rule 100016

Suspicious command execution indicators.

Rule 100017

Additional web attack and reconnaissance indicators.

Project Evolution

The architecture evolved as practical hardware and infrastructure constraints became part of the engineering challenge.

Phase 1 — Network Lab

Started with virtualization, networking fundamentals, VLANs, routing and firewall experimentation.

Phase 2 — Security Monitoring

Introduced Wazuh, endpoint telemetry, Sysmon, Suricata and centralized security monitoring.

Phase 3 — Cloud Experiment

Experimented with Oracle Cloud infrastructure, remote security monitoring and VPN connectivity.

Phase 4 — Fully Local SOC

Returned to a fully local VMware architecture to reduce cloud dependency and simplify experimentation.

Phase 5 — Detection Engineering

Focus shifted toward attack simulation, centralized logging, custom detections and investigation.
